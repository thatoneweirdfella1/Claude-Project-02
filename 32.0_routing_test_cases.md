# Phase 8, Item 32.0: Routing Test Cases
## Multi-Model Routing Decision Tree Validation

**Document**: Routing test cases for the three-tier model selection engine
**Framework**: Decision tree (3.14) + Model-question matrix (13.1-13.7)
**Total cases**: 25 (5 Phase 1 benchmarks + 20 new Phase 8 extractions)
**Test scope**: Verify routing engine assigns correct model tier across diverse question types and consequence levels

---

## Routing Framework Summary

**Decision Logic**:
1. User Override (hard stop if specified)
2. Consequence Gate: Consequence ≥ 4 → Opus-Thinking (mandatory)
3. Complexity Baseline: Score across 5 dimensions (Complexity, Evidence-Need, Ambiguity, Novelty, Scope)
4. Complexity Score Calculation: 
   - Consequence (weight: 5) 
   - Evidence-Quality Need (weight: 4)
   - Ambiguity (weight: 3)
   - Novelty (weight: 3)
   - Complexity (weight: 2)
   - Scope (weight: 2)
5. Safe Default: Opus-Fast when uncertain

**Tier Guidance**:
- **Haiku**: Factual lookup, product research, straightforward definitions, procedural output. Weak on evidence-quality nuance, conceptual precision, high-ambiguity cases.
- **Opus-Fast**: Technical troubleshooting, architectural decisions (moderate), comparison questions, framework generation. Sufficient unless deep reasoning or high error cost needed.
- **Opus-Thinking**: Conceptual precision (framing > facts), health/evidence with contested quality, deep multi-step reasoning, Consequence ≥ 4 scenarios.

## Validation Notes

**Routing Engine Test Design**:
- **Haiku cases** validate straightforward lookup, procedural, and low-ambiguity scenarios
- **Opus-Fast cases** test moderate complexity, multi-factor comparison, architectural decisions
