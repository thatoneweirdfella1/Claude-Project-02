# Phase 11: Multi-AI Conversation Mode with Account Rotation

**Optional expansion: Two models debate/synthesize, accounts auto-swap when tokens deplete**

---

## 11.0 CORE CONCEPT

After Stage 5 (single model answer), user can optionally toggle "Multi-AI Mode."

System then:
1. Picks a second model (Claude vs. GPT vs. Perplexity)
2. Runs the composed prompt through both
3. Shows both answers side-by-side or in a dialogue
4. User picks which is better, or sees them synthesized

**Account rotation:**
- You have 8 free accounts (Claude A/B/C/D, GPT A/B, Perplexity A/B)
- System pools them
- When Claude A hits token limit mid-conversation, Claude B auto-signs in
- Context is carried forward (conversation history passed to new account)
- User doesn't see the swap (or sees minimal notification)

## 11.1 THREE DIALOGUE MODES

### Mode 1: DEBATE
```
User question: "Should I switch jobs?"

Claude (Opus-Fast): [argues FOR switching]
GPT-4 (similar tier): [argues AGAINST switching]

User sees both, clicks one they agree with, or asks system to synthesize
```

**When to use:** Decisions where you want to see both sides. High ambiguity questions.

### Mode 2: CONSENSUS
```
User question: "Is the Jasion EB5 a good bike?"

Claude answer: [assessment + score 7/10]
GPT answer: [assessment + score 6/10]

System: "Both models agree this bike is mid-tier reliable. Confidence: 85%"
```

**When to use:** Factual questions where agreement increases confidence.

### Mode 3: SYNTHESIS
```
User question: "Career change or stay?"

Claude: "Switch if growth matters more to you"
GPT: "Stay if security matters more to you"

System: "The real decision is Growth vs. Security. Which do you prioritize?"
```

**When to use:** Complex decisions where opposing views reveal a deeper principle.

### Account Swap Logic
```python
function call_model_with_rotation(provider, prompt, conversation_history):
    
    # STEP 1: Find available account
    available = find_account(provider, tokens_remaining > 5000)
    
    if not available:
        // No account with tokens left, find one that's depleted
        depleted = find_depleted_account(provider)
        if depleted:
            // Reset its daily limit (free tier resets daily)
            reset_account(depleted)
            available = depleted
        else:
            // No accounts left, fall back to other provider
            return fallback_provider(prompt)
    
    # STEP 2: Call the account
    try:
        response = call_api(available.api_key, prompt, max_tokens=2000)
        log_usage(available.account_id, response.tokens_used)
        return response
    
    except TokenLimitError:
        // Mid-call limit hit, swap accounts
        new_account = find_next_available(provider)
        
        if not new_account:
            return error("No accounts available")
        
        // Carry context to new account
        carry_context = {
            "conversation_history": conversation_history,
            "prompt": prompt,
            "partial_response": response.partial
        }
        
        new_response = call_api(new_account.api_key, carry_context)
        
        log_swap(old=available.account_id, new=new_account.account_id, reason="token_limit")
        
        return new_response
```

## 11.3 CONTEXT TRANSFER ON SWAP

When an account runs out mid-response:

```python
function transfer_context(old_account, new_account, conversation_so_far):
    
    // Build carry-forward message
    carry = {
        "original_question": conversation_so_far.question,
        "conversation_history": conversation_so_far.messages,
        "partial_response_from_old_account": conversation_so_far.last_response.partial,
        "instruction": "Continue from where the previous account left off. Maintain tone and reasoning."
    }
    
    // Compress context if needed (if history is long, summarize)
    if len(carry.conversation_history) > 50:
        summary = summarize_history(carry.conversation_history)
        carry.conversation_history = summary
    
    // Send to new account with instruction to continue
    new_prompt = f"""
    [Previous conversation context]
    {json.dumps(carry)}
    
    [Continue your response from above]
    """
    
    return call_api(new_account.api_key, new_prompt)
```

## 11.9 TOKEN POOLING & ROTATION STRATEGY

**Daily reset schedule:**
```
Claude free tier: Resets 00:00 UTC
GPT free tier: Resets 00:00 UTC
Perplexity: Resets 00:00 UTC

System checks daily and updates pool status
```

**Account priority (when choosing which to use):**
1. Account with most tokens remaining
2. If tied, round-robin (balance usage)
3. If all depleted, wait for reset or fallback to other provider

**Fallback chain:**
```
Claude → GPT → Perplexity → (error if all exhausted)
```

## 11.11 COST & PERFORMANCE

**Token cost:**
- Single model: 2,000 tokens
- Debate mode: 4,000 tokens (2 models × 2,000)
- Consensus mode: 4,000 tokens
- Synthesis mode: 4,000 tokens

**Latency:**
- Single model: 2-5 seconds
- Debate mode: 4-10 seconds (parallel if possible)
- Account swap: +1-2 seconds (login overhead)

**Token pool management:**
- 8 free accounts × 100k tokens/day = 800k tokens/day total
- Average user: 50 questions/day × 2k tokens = 100k tokens
- Pool supports 8 concurrent users at full capacity

## 11.12 RISKS & MITIGATIONS

| Risk | Mitigation |
|------|-----------|
| Account login fails (captcha, 2FA) | Manual re-auth required; fallback to other provider |
| Context too large to transfer | Summarize history before carry-forward |
| Two models give conflicting answers | Synthesis mode resolves conflict into underlying principle |
| Accounts get rate-limited | Track API call frequency, back off if needed |
| User sees too many account swaps | Log silently; offer Settings toggle for notifications |
