```
Concept: A reverse proxy is a server that sits between clients and backend servers. 
It receives client requests, forwards them to the backend, and sends the response 
back to the client. The client never talks directly to the backend.

Why it exists:
- Load balancing: Distribute traffic across multiple backends
- Security: Hide backend IPs, add authentication/authorization
- Caching: Cache responses to reduce backend load
- SSL termination: Encrypt client connections without burdening backend
- Local routing: Direct requests to different backends based on path or hostname

Basic nginx config:
```
server {
    listen 80;
    location / {
        proxy_pass http://backend_server:3000;
        proxy_set_header Host $host;
    }
}
```
This says: "Listen on port 80. For any request, forward it to backend_server:3000. 
Pass along the original Host header."

Validation (test it):
```
curl http://localhost/
```
If you see your backend's response, it's working.

Common gotcha: Forget to set proxy_set_header, and the backend thinks requests are 
coming from localhost, not the original client. This breaks authentication checks.
```
