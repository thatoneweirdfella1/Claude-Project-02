## SECTION 1: SYSTEM OVERVIEW & ARCHITECTURE

### 1.0 Five-Stage Pipeline

The system is a sequential pipeline with feedback loops:

```
Stage 1: TRANSLATION       Stage 2: ROUTING       Stage 3: TECHNIQUE SELECTION
Input → Translate → Confidence Check → Route → Confidence Check → Select Techniques
                                                                          ↓
                                                                      Stage 4: COMPOSITION
                                                                      Compose Prompt
                                                                          ↓
                                                                      Stage 5: EXECUTION
                                                                      Call Model API
                                                                      Get Answer
                                                                          ↓
                                                                    Feedback Loop
                                                                    Log & Analyze
```

Each stage has:
- **Input contract:** What data must be present
- **Processing logic:** Core algorithm
- **Output contract:** What is produced
- **Validation:** How to know it worked
- **Failure handling:** What if it doesn't

### 1.2 Core Databases / Reference Libraries

You need these data structures accessible throughout:

1. **Prompt Library (10 categories, 46+ templates)**
   - Structure: `{category: string, name: string, template: string, model_tier: string, use_case: string}`
   - Access: Read-only lookup by category and use case

2. **Technique Library (T01-T18, fully documented)**
   - Structure: `{id: string, name: string, description: string, injection_point: string, selector_function: function, examples: string[]}`
   - Access: Read-only lookup by ID, score function, selector function

3. **Translation Operations Library (6 operations)**
   - Structure: `{operation_name: string, input_types: string[], execution_logic: function, validation: function, output_format: string}`
   - Access: Called in sequence, stateless

4. **Routing Decision Tree (20 rules + gates)**
   - Structure: `{rule_id: int, name: string, condition: function, action: string, confidence_weight: float}`
   - Access: Evaluated in order

5. **Model × Question Type Matrix**
   - Structure: `{model: string, question_type: string, suitability_score: float, reason: string}`
   - Access: Lookup for routing validation

6. **Technique × Question Type Matrix**
   - Structure: `{technique: string, question_type: string, effectiveness_score: float}`
   - Access: Lookup during technique selection scoring

7. **Technique Combination Rules (dependencies, conflicts, synergies)**
   - Structure: `{pair: [technique1, technique2], relationship: enum(DEPENDS, CONFLICTS, SYNERGIZES), details: string}`
   - Access: Consulted during conflict checking

8. **Pattern Database (for learning system)**
   - Structure: Time-series log of: question → routing → techniques → model response → user feedback → outcome
   - Access: Write-only during execution, read-only during pattern analysis phase

---

### 1.3 Key Design Constraints

**Confidence scoring is everywhere:**
- Translation outputs confidence (0-100)
- Routing outputs confidence (0-100)
- Technique selection scores each technique (0-15 scale)
- These scores determine branching: high confidence proceeds, low confidence asks clarification

**Cascade strategy:**
- If any stage fails to reach confidence threshold, don't proceed — ask user instead
- Example: Translation <60% confidence → ask clarifying questions, don't route
- Example: Routing <75% confidence → show options or escalate

**Stateless except for logging:**
- Each stage should not depend on state from previous stages except input/metadata
- All logging goes to pattern database (write-once, append-only)
- Pattern database is read during analysis phase, not during execution phase

### 2.1 Translation Algorithm Pseudocode

```python
function translate(raw_input, history, preferences):
    
    # STEP 1: Analyze input structure
    analysis = analyze_input(raw_input)
    // Returns: {has_emotional_markers, punctuation_abnormal, pronoun_count, 
    //          sentence_count, avg_sentence_length, topic_shifts, buried_requests}
    
    # STEP 2: Run translation operations in sequence
    current_text = raw_input
    operations_log = []
    
    for operation in [extract, reorder, normalize, clarify, surface, decompose]:
        if should_apply(operation, analysis):
            result = operation(current_text)
            if result.success:
                current_text = result.output
                operations_log.append(operation.name)
            else if operation.is_critical:
                return failure("Operation {op} failed critically", [clarifying_questions])
    
    # STEP 3: Extract final question(s)
    extracted_questions = extract_questions(current_text)
    
    # STEP 4: Validate extracted questions
    for q in extracted_questions:
        if not is_answerable(q):
            return failure("Question not answerable", [clarifying_questions])
    
    # STEP 5: Calculate confidence
    confidence = calculate_confidence(
        extraction_success = len(extracted_questions) > 0,
        scope_clarity = analyze_scope(extracted_questions),
        answerability = all(is_answerable(q) for q in extracted_questions),
        operation_success_rate = len(operations_log) / total_applicable_operations
    )
    
    # STEP 6: Return or ask clarification
    if confidence >= 80:
        return {translated_questions, metadata with confidence, operations_log}
    else if confidence >= 60:
        return {translated_questions, metadata with confidence and warning}
    else:
        return failure("Low confidence", clarifying_questions_for(raw_input))
```

### 2.2 Translation Operations (6 Core)

**Operation 1: extract_core_question()**
```
Input: raw_text with preamble/tangent
Logic: 
  - Find markers ("anyway", "but", "the actual question is", "bottom line")
  - Extract sentence/clause after marker
  - If no marker, use keyword clustering (TF-IDF on question words: "what", "why", "how", "should")
Output: core_question (string) or null
```

**Operation 2: reorder_context()**
```
Input: questions with context scattered
Logic:
  - Identify primary question vs. supporting context
  - Move context to front or footnote (decide based on relevance)
  - Re-order for: [context] → [question] → [constraints]
Output: reordered_text
```

**Operation 3: normalize_emotional_language()**
```
Input: text with emotional intensity (caps, repetition, punctuation)
Logic:
  - Replace caps with normal case
  - Collapse repeated punctuation (!!! → !)
  - Replace emotional intensifiers (HOLY SHIT → …, SO CRAZY → …)
  - Keep the underlying statement
Output: normalized_text
```

**Operation 4: clarify_scope()**
```
Input: question with ambiguous scope
Logic:
  - Identify scope markers ("broad", "specific", "quick answer", "detailed")
  - If absent, infer from question structure (yes/no → narrow, "how" → medium, "explore" → broad)
Output: question with explicit scope annotation
```

**Operation 5: surface_assumptions()**
```
Input: question with implicit assumptions
Logic:
  - Extract pronouns and check if referent is clear (e.g., "it", "that")
  - Extract implied constraints (budget, time, skill level)
  - Extract implied success criteria
Output: list of assumptions + clarification questions
```

**Operation 6: decompose_compound()**
```
Input: multiple questions bundled together
Logic:
  - Split on "and", semicolons, numbered lists
  - Identify logical dependencies (Q2 requires Q1 answer)
  - Separate dependent from independent questions
Output: [question1, question2, …] with dependency graph
```

### 3.1 Routing Algorithm Pseudocode

```python
function route_questions(questions, metadata, preferences):
    
    assignments = []
    
    for question in questions:
        
        # STEP 1: Check user override
        if preferences.preferred_model:
            assignments.append({
                question: question,
                model: preferences.preferred_model,
                confidence: 100,
                reasoning: "User override"
            })
            continue
        
        # STEP 2: Analyze question on 6 dimensions
        analysis = {
            complexity: score_complexity(question),      // 1-10
            domain: classify_domain(question),            // factual, analytical, creative, etc.
            scope: assess_scope(question),                // narrow, medium, broad
            certainty: assess_certainty(question),        // clear_answer vs. exploratory
            time_sensitivity: assess_time_need(question), // critical vs. flexible
            depth_need: assess_depth(question)            // surface vs. deep
        }
        
        # STEP 3: Apply consequence gate first (overrides all)
        consequence = assess_consequence(question)        // 1-5 scale
        if consequence >= 4:
            // High-stakes question, escalate tier minimally
            min_model = OPUS_FAST
        else:
            min_model = HAIKU
        
        # STEP 4: Apply 20 routing rules (in order)
        matched_rules = []
        for rule in ROUTING_RULES:
            if rule.condition(analysis):
                matched_rules.append(rule)
        
        # STEP 5: Determine primary model from matched rules
        if matched_rules is empty:
            model = default_model(analysis)  // Usually Opus-Fast
        else:
            // Get most specific rule (last matched)
            primary_rule = matched_rules[-1]
            model = primary_rule.action
        
        # STEP 6: Apply consequence gate constraint
        if model_tier_rank(model) < model_tier_rank(min_model):
            model = min_model
        
        # STEP 7: Calculate confidence
        confidence = calculate_confidence(
            agreement_score = count_rules_supporting_model(model) / total_rules,
            margin_score = gap_to_next_best_model(model),
            conflict_level = detect_conflicts(matched_rules)
        )
        
        # STEP 8: Handle low confidence
        if confidence < 75 and consequence >= 4:
            model = upgrade_tier(model)  // Escalate to safer model
        else if confidence < 60:
            // Show options to user
            return show_routing_options(question, matched_rules)
        
        assignments.append({
            question: question,
            model: model,
            confidence: confidence,
            reasoning: primary_rule.name if matched_rules else "Default routing"
        })
    
    return assignments
```

---

### 3.2 The 20 Routing Rules

Rules are evaluated in order. Each returns a model tier or null (didn't match).

```
Rule 1:  IF complexity < 3 AND domain = factual AND scope = narrow 
         THEN Haiku
         
Rule 2:  IF time_sensitivity = high AND token_cost_matters 
         THEN Haiku
         
Rule 3:  IF complexity 3-5 AND scope = narrow AND certainty = clear 
         THEN Haiku
         
Rule 4:  IF complexity 4-6 AND domain IN (analytical, comparative) 
         THEN Opus-Fast
         
Rule 5:  IF scope = medium AND ambiguity <= 2 
         THEN Opus-Fast
         
Rule 6:  IF domain = procedural AND complexity <= 5 
         THEN Opus-Fast
         
[... continue through Rule 20 ...]

Rule 20: IF confidence < 60 AND consequence >= 4 
         THEN Opus-Thinking (escalate for safety)
```

See COMPLETE_DETAILED_PROJECT_BLUEPRINT.md, item 3.14, for full 20 rules.

### 4.1 Technique Selection Algorithm Pseudocode

```python
function select_techniques(question, question_type, model, metadata):
    
    # STEP 1: Analyze need
    need_profile = {
        accuracy_critical: assess_accuracy_need(question),
        hallucination_risk: assess_hallucination_risk(question),
        bias_risk: assess_bias_risk(question),
        scope_clarity: assess_scope_clarity(question),
        ambiguity_level: assess_ambiguity(question)
    }
    
    # STEP 2: Score each technique T01-T18
    scores = {}
    for technique in TECHNIQUE_LIBRARY:
        relevance = score_relevance(technique, need_profile, question_type)     // 0-5
        impact = score_impact(technique, model)                                 // 0-5
        synergy_bonus = check_synergies_with_other_techniques(technique)        // 0-5
        complexity_cost = technique.token_cost                                  // 0-3
        
        scores[technique.id] = relevance + impact + synergy_bonus - complexity_cost
    
    # STEP 3: Filter by threshold
    candidates = [t for t in scores if scores[t] >= 7]
    
    # STEP 4: Check dependencies
    dependency_graph = build_dependency_graph(candidates)
    // Remove techniques with unsatisfied prerequisites
    candidates = candidates.filter(has_dependencies_satisfied)
    
    # STEP 5: Remove conflicts
    for pair in CONFLICT_PAIRS:
        if pair[0] in candidates and pair[1] in candidates:
            // Keep higher-scored one, remove other
            lower = min(pair, key=lambda t: scores[t])
            candidates.remove(lower)
    
    # STEP 6: Check budget
    max_techniques = MAX_BY_MODEL[model]  // Haiku: 6, Opus-Fast: 9, Opus-Thinking: 6
    total_technique_cost = sum(scores[t] for t in candidates)
    
    if len(candidates) > max_techniques:
        // Prune lowest-impact candidates
        candidates = sorted_by_score(candidates)[:max_techniques]
    
    # STEP 7: Order by dependency graph (topological sort)
    ordered = topological_sort(candidates, dependency_graph)
    // If no dependencies, use CANONICAL_ORDER: T03→T01→T04→T02→T08→T05→T06→...
    
    # STEP 8: Return
    return {
        selected_techniques: ordered,
        technique_scores: scores,
        confidence: confidence_from_score_distribution(scores[t] for t in ordered)
    }
```

```python
function compose(role, question, techniques, model):
    
    # STEP 1: Load template
    template = load_template(model)
    // Haiku template is lightweight, Opus template is full
    
    # STEP 2: Insert role + system constraints
    prompt = template.system_section
    prompt += format_role(role)
    
    # STEP 3: Insert translated question
    prompt += format_question_section(question)
    
    # STEP 4: Inject techniques in order
    for technique_id in techniques:
        technique = TECHNIQUE_LIBRARY[technique_id]
        injection = technique.format_for_injection(technique_id)
        prompt += injection
    
    # STEP 5: Add output format spec
    prompt += format_output_spec(question_type, expected_format)
    
    # STEP 6: Validate prompt
    validation_result = validate_prompt(prompt, model)
    if not validation_result.passed:
        prompt = recompose_with_fixes(prompt, validation_result.issues)
        validation_result = validate_prompt(prompt, model)
    
    # STEP 7: Return
    return {
        final_prompt: prompt,
        metadata: {
            techniques_injected: techniques,
            token_count: estimate_tokens(prompt),
            validated: validation_result.passed
        }
    }

function validate_prompt(prompt, model):
    checks = {
        has_system_constraints: "You are" in prompt,
        has_role_definition: specific_role_detected(prompt),
        has_question: "question" in prompt or "task" in prompt,
        techniques_in_order: verify_technique_order(prompt),
        has_output_format: "format" in prompt or "structure" in prompt,
        no_conflicts: no_conflicting_instructions(prompt),
        within_token_limit: estimate_tokens(prompt) <= MAX_BY_MODEL[model],
        scope_is_bounded: scope_limit_detected(prompt)
    }
    
    passed = all(checks.values())
    issues = [k for k, v in checks.items() if not v]
    
    return {
        passed: passed,
        issues: issues,
        checks: checks
    }
```

```python
function collect_feedback_and_log(
```

### 6.3 Pattern Analysis (Weekly/Batch)

```python
function analyze_patterns():
    
    // Group logged interactions by question_type
    groups = group_by(PATTERN_DATABASE, "question_type")
    
    for question_type, interactions in groups.items():
        if len(interactions) < 15:
            confidence = LOW
            continue
        
        // Analyze satisfaction by routing
        satisfaction_by_model = group_by(interactions, "routed_model")
        //  → {Haiku: avg_rating, Opus-Fast: avg_rating, Opus-Thinking: avg_rating}
        
        // Identify underperforming patterns
        if satisfaction_by_model[Haiku] < 3.5 and count(Haiku) > 5:
            // Haiku is underperforming for this question type
            recommendation = "Consider escalating {question_type} to Opus-Fast"
        
        // Analyze technique effectiveness
        technique_outcomes = {}
        for technique_id in T01..T18:
            cases_with_technique = [i for i in interactions if technique_id in i.techniques]
            if len(cases_with_technique) >= 3:
                avg_satisfaction = mean([c.outcome for c in cases_with_technique])
                technique_outcomes[technique_id] = avg_satisfaction
        
        // Surface recommendations
        if any(avg < 3.0 for avg in technique_outcomes.values()):
            low_performers = [t for t, avg in technique_outcomes if avg < 3.0]
            recommendation += f"Consider removing {low_performers} from {question_type}"
    
    return recommendations
```

```python
function apply_rule_refinement(recommendation):
    
    // Recommendation format:
    // "Consider escalating {question_type} to Opus-Fast"
    // "Consider adding T08 to {question_type}"
    // "Consider removing T12 from {question_type}"
    
    // Decision: Does recommendation have sufficient confidence?
    if recommendation.confidence >= 70% and sample_size >= 15:
        
        // Generate refined rule
        old_rule = find_rule_for(recommendation.question_type)
        new_rule = modify_rule(old_rule, recommendation)
        
        // Validate: Test new rule on next 10 questions of this type
        test_results = run_new_rule_on_holdout(new_rule, 10 questions)
        
        if mean(test_results) > mean(old_rule_results):
            // New rule is better, apply it
            ROUTING_RULES.update(new_rule)
            log_refinement(old_rule, new_rule, test_results)
        else:
            // New rule is worse or no improvement, revert
            log_refinement_rejected(new_rule, test_results)
```

## SECTION 12: TROUBLESHOOTING GUIDE

### Issue: Translation confidence always low
**Check:** Are translation operations failing silently? Are they removing too much text?
**Fix:** Add debug logging to each operation, verify it's not over-normalizing emotion.

### Issue: Routing assigns wrong models
**Check:** Are the 20 rules specified correctly? Is consequence gate working?
**Fix:** Run routing tests (32.0) in isolation. Print which rules matched.

### Issue: Technique conflicts keep appearing
**Check:** Is conflict detection running? Is the dependency graph correct?
**Fix:** List all selected techniques, manually trace through conflict check logic.

### Issue: Composed prompts fail validation
**Check:** Is output format spec missing? Are techniques injecting invalid syntax?
**Fix:** Print the composed prompt before sending to model. Check for obvious issues.

### Issue: Learning system doesn't detect patterns
**Check:** Do you have 15+ questions per type? Is the pattern database logging correctly?
**Fix:** Query the pattern database directly. Manually count interactions by type.
